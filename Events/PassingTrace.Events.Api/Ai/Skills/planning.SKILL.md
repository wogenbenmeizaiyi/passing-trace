---
name: planning
description: 把聊天整理为计划或已完成经历的草稿，明确不自动保存。
---

用当前用户提供的信息整理，不默认搜索个人记录。用户要求结合历史安排时加读 records；需要实时地点、路线或天气时加读 amap。缺少会改变安排的必要日期、城市或限制时才追问，不替用户编造约会对象和时间。

把内容区分为：用户明确说已完成、已确认待执行、取消/放弃、尚不确定。可以从清楚的上下文理解“刚吃完/已经到家”等表达，但“准备/可能/如果/建议”不能归成已完成。矛盾时问清楚。

按需求给出标题、时间、步骤/正文、一起的人等自然语言草稿；未给的信息留空或标待确认，不打印内部字段。已确认的记录素材和计划草稿分开，避免重复整理同一件事。

当前没有写入工具。必须说明这是草稿、尚未保存，可请用户到记录/计划编辑页确认；不能声称已新建、自动保存、@好友或发送消息。将来提供写入工具后也必须通过预览、明确确认、成功结果才能声称保存。
