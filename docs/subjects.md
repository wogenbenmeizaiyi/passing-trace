# 人物、宠物与物品

人物是用户私有的具体对象档案，类型为人、宠物和物品；车辆、房屋、自行车、收藏品通过物品细分类表达。所有权来自认证用户，档案不是平台账号或好友，不产生协作权限。

## 两套来源

| 来源 | 保存 | 展示 | 我的原记录与统计 |
| --- | --- | --- | --- |
| 原记录或计划 | `Event`、`SourceRevision` | 原记录列表，以及明确标记的档案时间轴 | 保持原范围 |
| 档案专属记录或计划 | `SubjectEntry`、`SubjectHistory` | 所属档案，以及明确标记的其他档案时间轴 | 不计入 |

`subject_timeline_reference` 只保存来源 ID 与展示入口，同一源不会复制。查询按来源类型和真实 ID 去重；源编辑、计划完成或取消直接反映到所有入口。移除标记只关闭入口。删除来源后已有引用显示失效，不泄露正文。首版只允许引用本人创建的 Event。

自己读取本人原 Event、自己所属的专属内容，以及其他人物内容对自己的明确标记。朋友专属内容标记小猫只进入朋友和小猫，不自动进入自己。人物标记、档案关系和平台共同参与者独立维护。

## 自身、关系和事务

`subject` 的部分唯一索引保证每个用户只有一个自身档案；数据库检查约束保护其人类型、进行中状态和未删除状态。增量迁移补齐 Events 数据库中已有记录、聊天、记忆和媒体的用户；新账号或没有活动的账号第一次通过认证访问 Events API 时自动初始化。自身名称固定标识为自己，Web 和 App 展示昵称及头像时使用账号资料，生活字段保存在档案模块。

新档案必须提交至少一个已有档案关系。图只有档案节点和档案关系，支持链、环、交叉关联、方向与起止日期。结束关系保留有效历史并显示灰线；误关联移除保留修订审计，但不再计入连通。记录、计划和生命周期节点不成为图节点或边。

手机新增及编辑关系使用独立表单页，按关联信息、关系方向、关系时间分区。方向为相互关联、本档案指向关联档案、关联档案指向本档案三个互斥选项，并显示两端名称。时间说明独立展示，保存操作固定在键盘上方；取消不写入，提交失败保留草稿，成功后回到档案并刷新关系。

手机档案详情的关系区域默认收起，摘要显示总数与历史关系数，新增入口常驻；展开后可以按档案名称或关系名称搜索、筛选当前或历史关系。维护列表限制高度并按需构建，展开状态按档案保存，编辑或删除后刷新数量。时间轴仅显示当前条件摘要，分组、内容类型、状态和日期范围统一在筛选面板中维护；取消及关闭不修改条件，应用后才重新查询，重置也需应用才生效。

手机时间轴按月或按日的日期标题可独立展开、收起，显示当前已加载条数；默认仅展开最近一组。工具栏在时间轴内滚动时固定，随时可全部收起或展开，记录卡片按需构建。刷新、加载更多及返回来源详情保留已有日期的展开状态，日／月状态分别维护。滚动后右下角提供“回到顶部”，返回档案资料，无需逐屏上滑；收起只改变展示，不修改来源或重新查询。

手机人物列表按需构建档案卡片，自身置顶，显示圆形头像、类型和生命周期状态标签。自身使用账号头像，普通档案封面经过认证媒体接口读取，加载失败时回退类型图标；车辆、房屋、自行车和收藏品使用独立图标，关系图同步类型图标。列表下方关系清单默认收起，展开后支持两端档案及关系名称搜索、当前／历史筛选和限高滚动，两端名称均可打开对应档案。底部导航及侧栏人物入口统一使用双人轮廓图标。

手机普通档案在基本信息中提供“头像”入口，支持人、宠物及物品的图片选择、圆形预览与裁剪、更换和移除。头像图片使用现有私有媒体服务上传，以 `coverMediaId` 保存，不占用或清除其他附件，保存档案后才生效；允许 JPG、PNG、WebP，原图最大 5MB，裁剪为 512×512 PNG。列表、关系图和档案详情显示同一头像，未设置或加载失败则显示类型图标；自身仍沿用账号头像。取消选图、取消裁剪或上传失败保留原头像，上传期间不能重复操作、保存或退出编辑页。

手机关系图中，已加载的头像铺满整个圆形节点并按圆形边界裁剪，名称和状态以白字叠放在底部渐变遮罩上。自身账号头像使用同样展示方式；未设置、加载中或读取失败仍显示原有图标与文字节点。节点大小、连线端点、拖动和点击区域保持一致。

手机头像在媒体地址请求、图片下载及解码期间持续显示默认图标，直到第一帧可显示才替换成照片；下载失败或图片损坏继续保留占位。列表、详情、编辑预览和账号头像同样遵循此规则，不用空的下载进度判定图片是否就绪。

Web 列表、详情和关系图统一使用圆形头像与类型图标，私有图片在请求及解码完成前保留默认图标，失败也不留空白；图内照片铺满圆形节点，并用渐变遮罩保留名称和状态的可读性。侧栏人物入口使用双人轮廓。资料按基本信息、生活字段、媒体与头像分区，窄屏纵向排列，字段定义收在“编辑字段”中，保存与取消保持可访问。手机单独上传的头像不在附件列表中时，Web 仍显示“保留当前头像”，编辑不会误清除它。

Web 关系列表默认收起，展开支持名称、关系名称与当前／历史筛选；维护清单限高滚动。新增及编辑关系、生命周期操作使用原生模态窗口，表单内容独立滚动，取消与保存固定在底部；危险操作收进档案的“更多操作”菜单，结束与删除使用危险色。标记人物通过可搜索的选择窗口维护，仅点击确定才应用草稿，取消保留原选择。记录页面使用“记录／计划”称呼，来源标签分别显示“原记录”和“来自人物”。时间轴日期组可独立收起、全部收起或展开，默认展开最近一组，并按档案及日／月保存展开状态；工具栏可返回资料。折叠不改变源内容。

Web 人物关系图铺满侧栏右侧的工作区，不使用居中内容宽度或固定百分比高度；顶部紧凑工具栏保留搜索、类型、视图切换、回到自己和建档，画布占满剩余空间。列表模式在同一工作区内独立滚动，小屏工具栏换行，不挤出画布或产生横向滚动。尺寸变化保留原中心图点和缩放级别，返回时结合已保存画布尺寸恢复视角，离开后停止尺寸观察。

Web 和手机的圆形节点支持直接拖动，连接节点通过弹簧拉力维持约 260 个布局单位的舒适距离；拉远时相连节点跟随，靠近时斥力与碰撞约束保证圆形节点不重叠。被拖动节点固定在指针下，松手后整图继续通过阻尼调整并自动停稳；首次打开也会整理布局，连线同步更新。复杂交叉关系下的最终距离由整图约束共同决定。图上仅显示箭头，单向关系使用单箭头，双向关系使用双箭头；关系名称保留在资料与关系列表。空白画布仍支持平移、缩放，点击节点进入档案，返回及列表切换保留布局。位置只保存在当前用户的本地视图状态，不修改服务端关系；“回到自己”定位已移动的自身节点。Web 还支持聚焦节点后使用方向键调整位置。动画在稳定或离开视图后停止，不持续占用渲染帧。

修改、替换端点、删除档案和移除误关联在同一个用户级 PostgreSQL advisory transaction lock 下检查所有未删除档案到自己的无向连通性。取得锁后刷新旧跟踪实体；断连操作拒绝并返回受影响名称，不自动重连或级联删除。档案软删除保留原 Event、专属内容、媒体和修订。

Core 定义领域模型以及 `ISubjectRepository`、`IEventSubjectService`、`ISubjectMediaQueries`。应用服务 `Subjects/SubjectService.*` 处理业务，EF 查询与锁位于 `Infrastructure/Persistence/Subjects`。人物和 AI 应用代码不引用 EF，不返回 `IQueryable`。原 Event 修改的人物标记和其来源修订处于同一工作单元。

## 字段和生命周期

字段用稳定 GUID，支持 `text`、`number`、`date`、`boolean`、`select`、`phone`。数字单位、字段名称与值随专属修订保存；已有实际或预期历史的字段不能改变类型或单位，移除字段保留历史。预设可以增删：人的生日、身高、体重、电话；宠物的品种、生日、到家日期、体重；车辆的型号、车牌、价格、里程；房屋的地址、面积、价格；自行车的型号、车架号、价格。

建档生成初始专属记录，直接资料值修改也生成专属记录。当前值按所属档案未删除、已实际发生的变化时间回算，补录旧值不覆盖新值；修改或删除内容后重新计算。普通 Event 引用不修改字段。专属计划的 `fieldChanges` 是预期值；完成必须明确实际时间和 `actualFieldChanges`，保持同一内容 ID，不自动采用预期值。

生命周期支持结束、恢复、纠正，节点保存在 `subject_milestone` 并汇入时间轴。结束原因区分离世、关系结束、出售、转赠、丢失、报废和其他；物品不能标为离世。离世只能纠正误标，生日年龄在离世日期停止增长，关系结束不停止年龄。结束期间仍可追加内容和计划，并显示期间标识。

结束预览列出所属待执行计划，默认保留。取消时提交每个计划 ID 和版本；引用来的计划不自动取消。其他标记档案看到相同取消结果，恢复不恢复已取消计划。所有版本冲突和失败操作回滚。

手机档案详情的结束、恢复、纠正和删除操作集中在右上角“更多操作”，资料区不再常驻这些入口。结束与删除的菜单文字、图标采用主题危险色，结束确认按钮为红色“确认结束”，删除仍通过原有按钮授权；取消保留当前档案且不提交业务变更。自身档案没有此菜单，离世档案仅能纠正误标，执行期间禁用菜单以阻止重复操作。

生命周期弹窗将档案说明、状态信息和待执行计划分区展示，日期、原因与说明之间保留间距。表单及计划列表可滚动，底部取消与确认按钮固定显示；小屏、大字体及键盘弹出时内容仍可访问。恢复与纠正使用各自的说明，所属计划仅在结束操作中列出，默认保留，提交时仍携带所选计划的真实 ID 和版本。

## 接口

接口前缀 `/api/v1/subjects`，都需要认证，用户 ID 由服务器取得。修改请求需要 `If-Match: "version"`；创建档案与内容支持 `Idempotency-Key`，同一键不同参数返回冲突。

| 方法与路径 | 功能 |
| --- | --- |
| `POST /self` | 幂等初始化自身 |
| `GET /`、`GET /graph`、`GET /presets` | 列表、人物关系图、字段预设 |
| `POST /`、`GET /{id}`、`PATCH /{id}` | 建档、读取、局部编辑 |
| `POST /{id}/relations`、`PATCH /relations/{id}` | 新增关联、编辑信息或替换端点 |
| `GET /{id}/history` | 档案修订 |
| `GET /{id}/timeline` | 双来源时间轴；day/month、时区、日期、类型、状态、游标分页 |
| `POST /{id}/entries`、`GET /entries/{id}`、`PATCH /entries/{id}` | 独立专属内容 |
| `POST /entries/{id}/decision` | 完成或取消专属计划 |
| `GET /{id}/lifecycle/preview`、`POST /{id}/lifecycle` | 预览所属计划与历史，提交生命周期变化 |
| `POST /delete-requests` | 为档案、专属内容、误关联创建按钮授权 |

原记录创建和编辑增加可选 `subjectIds`；未传保持兼容，更新时保留已有标记，空数组移除标记。

删除接口不暴露实际执行方法。`delete-requests` 仅接受类型、真实目标 ID、请求 GUID，返回绑定用户和会话的待授权提示。手机手动删除在当前档案或内容页弹出确认框，取消后留在原页，成功后才刷新关系或返回；断连、过期及版本变化的结果在确认框内显示。AI 申请及 Web 手动申请在聊天输入框上方使用确定／取消。两种界面共用同一个授权决定接口，仅发送决定，不允许替换目标。授权 15 分钟有效，确认重新检查目标版本、所有权和图连通；重复确认返回原结果，自身不允许申请删除。AI 与手动删除使用同一事务和持久化回执。

迁移 `20261001043116_AddSubjects` 新增七张表及原 Event/SourceRevision 的标记快照字段；已有记录默认空标记。历史媒体引用、资料变更、字段回算和数据版本在同一事务提交。人物专属内容保持独立，不作为原事件分析、统计或长期记忆输入；AI 通过档案与时间轴查询获得来源明确的数据。

## 媒体与三维

图片、视频、GLB 复用认证媒体上传、确认和读取服务。`MediaKind.Model=4`、MIME `model/gltf-binary`；服务端检查 GLB 2 魔数、版本、总长度、块顺序和内嵌资源，不允许外部贴图或缓冲区 URL。GLB 默认文件限制为 100 MiB。`GET /api/v1/media/{id}` 返回认证元数据；历史和当前引用经 Core 媒体查询端口阻止误删除。

Web 附件进入可见区域或点击后才下载，按需加载 `@google/model-viewer`，解码器放在 `public/model-decoders`；Flutter 使用 `model_viewer_plus`，渲染脚本由依赖包本地提供，Draco/KTX2/Meshopt 从应用 assets 提供。Meshopt 的本地脚本将上游模块的 export 转为全局导出，以适配渲染器的普通 script 加载方式。手机模型先经过认证下载到临时私有目录，仅选中模型和白名单解码资源通过随机路径的回环服务器提供；离开时关闭服务和媒体控制器并移除临时文件。关闭 AR，WebView 导航只允许回环地址，不能打开外部应用。两端支持旋转、缩放、重置、加载错误与重试。

参考：[model-viewer 加载配置](https://modelviewer.dev/examples/loading/)、[Flutter 渲染器文档](https://pub.dev/packages/model_viewer_plus)。解码资源来自 Three.js，随附 LICENSE；升级渲染依赖时同步两端本地解码资源。

## 验证

本地 `dev` 账号的演示初始化会创建七份普通档案：朋友、亲人、母猫、小猫、汽车、自行车、房屋。包含长链、交叉关系、历史关系、字段变化、专属待执行计划、已结束档案，以及原记录明确标记人物的双来源示例。启动 AppHost 的现有演示初始化会一并补齐；单独补人物可运行 `python tools/seed_development_subjects.py`。脚本只接受回环服务地址，使用开发自动登录和认证应用接口；稳定幂等键避免重复，不覆盖已有编辑或恢复软删除档案。示例联系方式和资产信息均为虚构。

后端 `SubjectServiceTests` 验证两来源隔离、自身保护、引用同步、字段回算、生命周期、用户隔离、版本、幂等、并发连通、回滚、授权及历史媒体引用保护。`GlbValidatorTests` 验证格式及资源限制。Web `subjects.spec.ts` 与 `subject-media.spec.ts` 验证节点拖动与避让、箭头、键盘移动、来源链接、计划实际值、生命周期默认计划保留、授权入口、AI 引用、视图恢复、按需加载、媒体重试和资源释放。手机 `subjects_test.dart` 与 `subject_graph_test.dart` 验证筛选应用与取消、拖动避让、密集节点、缩放后的拖动、画布平移缩放、布局恢复、自身账号资料、字段同步、计划完成、生命周期、真实链接和小屏授权。

Web `subjects-ui.spec.ts` 补充头像请求与解码占位、过期请求释放、自身头像同步、关系收起和筛选、人物选择取消与跨筛选勾选、时间轴收起恢复与档案隔离、电话号码／布尔值，以及保留手机头像和局部编辑回执。布局在本地真实浏览器的桌面与 390px 窄屏验证，包含表单溢出、模态窗口和固定操作区。

Android 已有 `internal` 与 `production` 构建变体；本模块调试验证使用 `flutter build apk --debug --flavor internal`，产物在 `build/app/outputs/flutter-apk/app-internal-debug.apk`。

首版不增加记录之间的线、字段模板管理、三维建模、资产估值和自动提醒。
